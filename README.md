# SparseGuard

An INT8 MLP inference accelerator for edge devices, with instruction-driven execution (ASIP), skipping of all-zero weight blocks (`MAC_SKIP`), and a secure boot based on SHA-256 challenge-response. Target: Cyclone V FPGA (DE10-Nano). Built for the **PERURI Chip Hackathon 2026**, category IC Chip Design & FPGA Implementation (AI / Edge Accelerator).

Case study: machine vibration anomaly detection (normal vs. bearing fault) from 16 statistical features per signal window, using the CWRU dataset.

> **Status:** the design is complete, synthesized, and verified at the RTL simulation level (Verilator + cocotb). It has **not been tested on a physical board** and **power consumption has not been measured**. See [Limitations](#limitations-and-what-is-not-yet-proven).

## Feature summary

- **Instruction-driven VPU.** The model runs from a 1 KB bytecode image (256 words x 32 bits) produced by a Python compiler, so weights and layer topology can change without modifying the RTL.
- **Block sparsity by the compiler.** A block of 4 weights that is entirely zero is compiled into `MAC_SKIP`, with no priority encoder in hardware.
- **Secure boot.** The blob and a tag are sent over SPI. The hardware computes SHA-256 over `K || N || blob` on the fly and allows execution only if the result equals the tag from the host. `K` is a 128-bit secret key and `N` is a 64-bit nonce generated by the device on every boot.
- **Small footprint.** 2,198 ALMs (5%), 1 M10K block, 7 DSP blocks on a Cyclone V 5CSEBA6U23I7.

## Architecture

```
 Host (MCU/PC)
     | SPI (MOSI, SCLK, CS_N, MISO)
     v
 spi_slave --> sparseguard (main FSM) --+--> vpu_ram (1 KB M10K)
                    |                   |        |
                    |                   |        v
                    |                   |   vpu_decoder (fetch-decode-execute)
                    |                   |        |  MAC_EXEC / MAC_SKIP
                    +--> sha256_core    |        v
                    |        |          |   mac_array (4-lane INT8) --> relu_quant --> output_cmp --> alarm LED
                    v        v          |
              integrity_boot (digest == tag?)
```

Main FSM: `NONCE -> BOOT -> TAG -> VERIFY -> WAIT_FEAT <-> INFER`, with `ERROR` if verification fails (locked until reset).

### Model

MLP 16 - 16 - 1: 16 INT8 features, 16 hidden neurons (ReLU + requantization), and 1 output compared against a threshold to raise the alarm. INT8 weights, INT32 biases, INT32 accumulators. 75% pruning on layer 1 (64 of 256 weights are nonzero).

### Instruction set (32-bit: opcode `[31:24]`, operand `[23:0]`)

| Opcode | Name | Function |
| :--- | :--- | :--- |
| `0x01` | `CHECK_NONCE` | Blob format version check (24-bit constant). It is **not** replay protection; replay is handled by the challenge-response protocol below. |
| `0x02` | `LOAD_BIAS` | Loads layer 1 biases (16 words) and the layer 2 bias (1 word). |
| `0x03` | `LOAD_PARAMS` | Loads the requantization multiplier `M`, `shift`, and the threshold. |
| `0x04` | `MAC_EXEC` | Executes `n` weight words; each word is 4 INT8 MACs in 1 cycle. |
| `0x05` | `MAC_SKIP` | Advances the feature index without activating the MACs (all-zero weight block). |
| `0x06` | `SWITCH_L2` | Writes the last layer 1 neuron and switches to layer 2. |
| `0x07` | `FINISH` | Ends inference (ReLU, threshold comparison, alarm). |
| `0x08` | `NEXT_NEURON` | Moves to the next neuron (not emitted after the last neuron). |

## Secure boot protocol

All phases run over SPI (mode 0). After reset the device waits for the nonce phase.

| Phase | Host sends | Device |
| :--- | :--- | :--- |
| 1. NONCE | One CS transaction, 10 bytes (byte 0 = `0xA5` as the request, the rest `0x00`) | Latches a 64-bit nonce from a free-running counter on the first CS falling edge, then returns it over MISO, MSB first, on bytes 1 through 8 (0-indexed). |
| 2. BOOT | 1024-byte blob | Writes the blob to `vpu_ram` (little-endian) and hashes `K (16 bytes) || N (8 bytes) || blob` on the fly. |
| 3. TAG | 32-byte tag = `SHA256(K \|\| N \|\| blob)` | Stores the tag (it is not hashed). |
| 4. VERIFY | - | Digest equals tag: proceed to `WAIT_FEAT`. Mismatch: `integrity_fail`, `led_error` lights up, and the FSM locks until reset. |
| 5. INFER | 16 INT8 feature bytes per inference | Runs the VPU; result on `led_alarm`. MISO status byte: bit 3 `integrity_fail`, bit 2 `alarm`, bit 1 `done`, bit 0 `busy`. |

Host side (Python):

```python
import hashlib
nonce = bytes(rx[1:9])                               # from MISO during the NONCE phase
tag = hashlib.sha256(KEY + nonce + blob).digest()    # KEY = 16 bytes, same as rtl/secret_key.svh
# send: blob (1024 bytes) followed by tag (32 bytes)
```

### Threat model

| Protected | Not protected |
| :--- | :--- |
| Blob modification in transit (MitM over SPI / OTA) | Physical extraction of the key from the bitstream |
| Blobs from a party without the key | Side channels (DPA/CPA), voltage or clock glitching |
| Replay of an old blob + tag (the nonce differs on every boot) | Model confidentiality: the blob is sent in plaintext over SPI |

Integrity uses a secret-prefix SHA-256 MAC over fixed-length messages. HMAC-SHA256 is the standard construction and is a natural next upgrade.

## RTL modules

| Module | Function |
| :--- | :--- |
| `sparseguard_top.sv` | I/O wrapper for the DE10-Nano (SPI, busy/done/alarm/error LEDs). |
| `sparseguard.sv` | Main FSM: nonce, boot, tag, verification, and inference phases. Generates the nonce from a free-running counter. |
| `spi_slave.sv` | SPI slave interface (mode 0), synchronization to the system clock. |
| `sha256_core.sv` | Streaming SHA-256. Injects `K \|\| N` before the blob. |
| `integrity_boot.sv` | Compares the digest with the host tag; holds the verification result. |
| `vpu_ram.sv` | 256 x 32-bit memory (1 M10K block) for the bytecode. |
| `vpu_decoder.sv` | ASIP core: fetch-decode-execute for the ISA above. |
| `mac_array.sv` | 4-lane INT8 MAC with an INT32 accumulator, per cycle. |
| `feature_buf.sv`, `hidden_buf.sv` | Input feature buffer (16 bytes) and hidden-layer activation buffer. |
| `relu_quant.sv` | ReLU and INT32-to-INT8 requantization with rounding. |
| `output_cmp.sv` | Threshold comparator for the alarm signal. |
| `reference_digest.sv` | Leftover from the old digest-ROM scheme; **no longer used**. |
| `secret_key.svh.example` | Test key template (see the Key notes below). |

## Model and training results

- Data: CWRU Bearing Data Center (`data/raw/*.mat`). 2048-sample windows with a hop of 1024, 16 statistical features per window (mean, std, rms, abs mean, min, max, peak-to-peak, variance, skewness, kurtosis, crest/shape/impulse/clearance factor, mean square, zero-crossing rate).
- Split: the train and test sets are assigned per recording file (the `split` column in `model/prepare_cwru.py`). Within each training file, the first 70% is used for training, the middle 10% is discarded as a temporal gap, and the last 20% is used for calibration.
- Pruning is selected on the calibration set: maximum sparsity with a balanced accuracy drop of at most 0.01 and a recall drop of at most 0.02. The selected value is **75%**.

Results on the test set (940 windows: 234 normal, 706 anomalous), after 75% pruning:

| Model | Accuracy | Recall | Precision | F1 | False negatives |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Float, pruned | 0.9979 | 0.9972 | 1.0000 | 0.9986 | 2 |
| INT8 | 0.9979 | 0.9972 | 1.0000 | 0.9986 | 2 |

Source of the numbers: `artifacts/pruning_selection.json` and `artifacts/quant_results.json`. Accuracy before pruning reaches 1.0 on both calibration and test, so this task is relatively easy on CWRU data; do not extrapolate to real machine conditions.

## Verification

All tests use cocotb + Verilator against the RTL (`tb/test_security.py`, 8 tests). Latest result: **8 passed, 0 failed**.

| Test | What it proves |
| :--- | :--- |
| `test_acc2_bit_exact` | For 64 INT8 test vectors (CWRU), the RTL layer 2 accumulator (INT32) equals an integer model computed directly from the contents of `vpu_blob.bin`, and the alarm matches the label in the CSV. |
| `test_tamper_single_bit` | Flips 1 bit at 10 blob positions (bytes 0, 1, 2, 3, 4, 100, 200, 500, 750, 1023) with a tag computed from the original blob: `led_error` goes high and `led_done` never goes high even when features are sent. |
| `test_tamper_tag` | Flips 1 bit in the tag: rejected. |
| `test_wrong_key` | The tag is computed with a key that differs by 1 byte: rejected. |
| `test_tamper_nonce` | The host uses a nonce that differs by 1 bit from the one the device issued: rejected. |
| `test_replay` | A valid blob + tag from session 1 is sent in session 2 (different nonce, with `N2 != N1` asserted): rejected. With a tag computed from the session 2 nonce: accepted. |
| `test_host_starts_late` | The host starts SPI long after reset (20 us). This test fails if the `nonce_ready` gate in `sha256_core` is removed, so it acts as a regression test for the premature nonce injection bug. |
| `test_nonce_latch_once` | The nonce does not change if CS falls again while still in the NONCE phase. |

The golden model is computed from the blob, not from the `acc2` column in `artifacts/int8_test_vectors.csv`; that column is not used for the accumulator.

## How to run

### Simulation

Requirements: Python 3, Verilator 5.036 or newer, cocotb 2.x, numpy.

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install "cocotb>=2" numpy
cd tb
make
```

The Makefile copies `rtl/secret_key.svh.example` to `rtl/secret_key.svh` if it does not exist. The tests use the test key written in `test_security.py`; if you change the key in `secret_key.svh`, change `KEY` in the tests to match.

### Regenerating the model and blob

```bash
pip install numpy scipy scikit-learn joblib
python model/prepare_cwru.py      # features from data/raw -> data/processed/cwru_features_16.npz
python model/train_calibrated.py  # train + calibrate
python model/select_pruning.py    # select 75% pruning
python model/compiler_vpu.py      # artifacts/vpu_blob.bin
```

`vpu_blob.sha256` is output from the old scheme (a hash with a fixed prefix) and is no longer used by the hardware. For the board, the host computes the tag with `K` and the device nonce.

### Synthesis (Quartus Prime 25.1)

1. Copy `rtl/secret_key.svh.example` to `rtl/secret_key.svh` and **replace it with a private key** for the board.
2. Open `quartus/SparseGuard.qpf`. If Quartus cannot find `secret_key.svh`, add the `rtl` folder to the Search Path (Assignments, Settings, Compiler Settings, Verilog HDL Input).
3. Run Full Compilation. Reports are written to `quartus/output_files/`, and the latest reports are included in the repository.

## Limitations and what is not yet proven

- **Not tested on a board.** All verification is RTL simulation. Testing the `.sof` on the DE10-Nano and SignalTap analysis are scheduled for the bootcamp stage.
- **Power not measured.** There is no power-saving claim. A small area does not automatically mean low dynamic power.
- **The nonce is not a TRNG.** The nonce comes from a free-running 64-bit counter, latched on the first CS falling edge. It does not repeat while the board stays powered, but it depends on host timing. After a power cycle the counter restarts from zero; a highly deterministic host could produce the same nonce. For production use a true random source (for example a ring-oscillator TRNG).
- **The key lives in the bitstream.** There is no protection against physical extraction. The example key in `secret_key.svh.example` is **public**: use it for simulation only, and use a private key for the board or demos.
- **The model is not kept secret.** The blob is sent in plaintext; the security provided is integrity, authenticity, and freshness, not confidentiality.
- **SPI speed limit.** `sha256_core` has no buffer. After each 64-byte block, compression takes about 65 clock cycles; a byte arriving in that window is lost. The theoretical SCLK limit is about 6.15 MHz for a 50 MHz clock. Simulation uses an SCLK:clock ratio of 1:20 (equivalent to 2.5 MHz at 50 MHz), and the nonce readback margin is also thin, so use a low SCLK.
- **Message length limit in `sha256_core`.** Padding is only correct when the message length mod 64 does not fall in 56 to 62. The SparseGuard message (24 + 1024 = 1048 bytes, mod 64 = 24) is safe; do not change the blob length without fixing `ST_PAD`.
- **`MAC_SKIP` savings not measured.** Unstructured pruning yields only 25 of the 64 layer 1 blocks being entirely zero; the analytical estimate of the cycle saving is about 15% (not verified in simulation). Block-aware pruning and merging consecutive `MAC_SKIP` instructions would improve it.
- **`CHECK_NONCE` in the blob** is only a static version check.
- The script that generated `artifacts/int8_test_vectors.csv` is not included in the repository.
